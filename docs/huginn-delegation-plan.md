# 후긴 이름 변경과 위임 작업 보기

## 목표와 설계

표시 이름은 Huginn(후긴)이다. 오딘의 까마귀를 모티브로 한 새 앱 아이콘을 앱, 웹, 설치 파일에 함께 사용한다. 기존 사용자의 데이터 경로·앱 식별자·업데이트 저장소는 유지해 새 설치로 분리되지 않게 한다.

위임 작업은 부모의 작업 상세에 접힌 목록으로 둔다. 목록을 펼치면 담당, 상태, 경과 시간과 지시·활동·결과가 보인다. 완료된 외부 평가를 사이드바에 다시 나열하지 않는다. 자식 상세에는 원래 위임 지시와 부모 작업으로 돌아가는 연결을 제공한다.

대화의 명시적인 위임 도구 ID, 자식 ID, 실행 출력 연결만 사용한다. 같은 제목·Jira 번호를 근거로 관계를 추측하지 않는다. 읽을 수 없는 기록은 미확인으로 표시한다. 오래된 활동을 완료로 간주하지 않는다. 지시·결과는 원문 발췌이며 AI 요약·목표 이탈 점수·추가 모델 호출을 사용하지 않는다.

## 구현 계획

- [x] 위임 데이터: Claude 도구 호출과 결과, Claude 하위 기록, Codex 협업 기록에서 지시·활동·결과·시간과 부모 연결을 수집한다. 기존 증분 읽기와 캐시를 활용하고 개수·본문 길이를 제한한다.
- [x] 화면: 부모 아래 접힌 위임 목록, 지시/결과 짝, 근거 있는 대기 사유와 시간, 부모 탐색을 추가한다. Claude·Codex를 동일하게 처리한다.
- [x] 브랜드: 승인된 Twins 원본을 작은 크기에서도 확인하고 적용했다. 표시 이름과 설치 파일·네이티브 창·웹 이름을 변경하고 기존 데이터·업데이트 호환성을 보존했다.
- [x] 검증: 명시적 관계·잘못된 관계·중단/대기/완료·손상된 기록·긴 입력·화면 이스케이프를 회귀 시험한다. Python/Node/Go 시험과 다크·라이트·좁은 화면 렌더를 확인한다. 가능하면 패키지 빌드로 설치 파일 표시 이름과 아이콘도 검증한다.

## 확인할 경계

- 부모의 과거 작업에서 시작한 위임이 현재 작업으로 옮겨 붙지 않아야 한다.
- 자식의 기록을 읽지 못했거나 활동이 멈춘 것을 완료로 표시하지 않는다.
- 여러 위임이 동시에 실행돼도 지시와 결과를 도구 ID로 짝짓는다.
- 여러 단계의 부모 연결 및 누락된 부모·순환 관계에서 화면 탐색이 깨지지 않는다.
- 기존 Forkrail 설치 데이터와 업데이트 식별자를 보존한다. 공개 GitHub 저장소 이름 변경은 앱 표시 이름 변경과 분리한다.

## 검증 결과 · 2026-11-19

- macOS arm64 rc.4 후보 빌드 및 ZIP/DMG 복사 설치의 실제 WebView·내장 서버 실행/종료 시험 통과. 임시 사용자 데이터 보존 확인. 서명되지 않은 로컬 후보이며 공개 릴리즈는 만들지 않았습니다.
- Windows x64 네이티브 코드는 교차 컴파일을 통과했으며, 이후 Windows 실제 설치도 아래 CI 실행에서 검증했습니다.
- 구 Forkrail의 데이터 경로·API·배포 파일 이름·GitHub 주소는 호환용으로 유지합니다. macOS의 새 Huginn.app은 이전 Forkrail.app과 파일명이 달라 수동 이전 절차를 README와 업데이트 안내에 적었습니다.

## Twins 확정과 전체 톤 적용

2026-11-19 사용자가 2번 Twins를 선택하고 앱 전체 톤도 아이콘에 맞추도록 요청했습니다. 선택 원본을 앱·웹·설치 파일에 적용합니다. 기존 다크 구조에 따뜻한 먹색·아이보리·황동색을 적용하며 작업 상태색은 구별 가능하게 유지합니다.

- [x] 공통 색상 파일로 작업 보드·통계·설정·작업 기록·네이티브 오류 화면을 통일했다.
- [x] 승인된 Twins 원본으로 웹·ICNS·ICO를 만들고 DMG 배경을 맞췄다. 앱 PNG와 선택 원본의 바이트 일치를 확인했다.
- [x] 임시 데이터로 1440px·390px 화면 20개를 렌더했다. 설정 5개 탭, 스킬 선택·요청 입력, 연결 편집, 작업 기록을 포함하며 스크립트 오류와 문서 가로 넘침은 없었다.
- [x] 주요 글자·상태색은 바탕·카드·입력 배경에서 4.5:1 이상의 대비를 확인했다. 비활성 점 색은 글자색과 구분한다.
- [x] 네이티브 앱에서 공통 CSS가 차단되는 문제를 실제 WebView 검사로 재현했다. 명시적 경로 허용을 추가하고 macOS·Windows 앱 경로의 프록시 회귀 시험 및 Go 전체 시험을 통과했다.
- [x] 수정본 macOS arm64 rc.4를 다시 빌드했다. ZIP 실행 및 DMG에서 임시 Applications로 복사한 앱의 WebView·내장 서버 시작/종료·테마 로딩·사용자 데이터 보존 검사를 통과했다. Windows x64 교차 컴파일과 아래 실제 설치 검사도 통과했다.

현재 결과물은 테스트 후보이며 공개 배포나 사용자의 Applications 설치는 수행하지 않았다. 브라우저 화면 검수에는 임시 데이터를 사용했다.

## Windows 실제 설치 검증 · 2026-11-19

[GitHub Actions 44463453813](https://github.com/nimo0711/huginn/actions/runs/44463453813)에서 소스 커밋 `9daab448730090da8ee469f1d899e2d32564c96f`의 1.2.0-rc.4를 검증했습니다. 이 실행에는 Windows x64, Apple Silicon Mac, Intel Mac이 모두 포함되며 세 대상 모두 통과했습니다.

Windows Server 2022의 일회용 환경에서 NSIS 설치 프로그램을 자동 실행했습니다. 다음 항목을 실제 파일·레지스트리·서비스·WebView로 확인했습니다.

- 사용자 단위 설치와 설치 경로·제거 항목 등록
- 설치본과 ZIP 실행본의 앱 화면·공통 테마·내장 서버 실행 및 종료
- 사용 중인 파일이 있을 때 업데이트 거부, 앱 종료를 기다린 뒤 업데이트, 이전 서비스 파일 정리
- 사용 중인 파일이 있을 때 제거 거부, 정상 제거 시 앱 파일·등록 정보 삭제
- 설치·업데이트·제거 전 과정에서 시험용 사용자 데이터 보존
- 설치 파일과 증거를 내려받아 SHA-256·대상 플랫폼·버전·미커밋 변경 없는 정확한 소스 커밋 재검증

Windows 설치 마법사를 사람이 클릭하는 수동 검사와 서명·SmartScreen 평판 확인은 이 자동 검증 범위에 포함하지 않습니다. 결과물은 서명되지 않은 테스트 후보입니다. 이 기록 이후의 문서 변경은 위에서 검증한 실행 코드 커밋과 구분합니다.
